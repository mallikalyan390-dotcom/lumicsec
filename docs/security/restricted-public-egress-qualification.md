## 1. Real kernel-enforced *local* exact destination allowlist

New `restricted-egress-firewall.ts` compiles a deterministic, exact-IP IPv4/IPv6 nftables `inet` OUTPUT policy: **default DROP, TCP/443 only to every explicitly listed exact IP**. Reject empty/oversized/duplicate lists, CIDRs, unsafe ports, unsafe/malformed/non-public addresses, metadata, RFC1918, carrier NAT, IPv4-mapped IPv6 and non-global IPv6 for public policy. Public sample IPv4+IPv6 rules compile **offline only**; return `executionAllowed:false` and cannot initiate any network request. Controlled test fixture exception requires explicit `controlledFixtureOnly:true` and a synthetic RFC1918 Docker address; it cannot admit public targets and must never be exposed to customer API routes. Original public DNS A/AAAA `resolveWebPublicAddresses`, all-answer public validation, exact origin/path and pinned TLS code remain unchanged. No real public DNS has been qualified.

**Real `pnpm test:restricted-egress` evidence:** Ephemeral uniquely named Docker `--internal` bridge, two separately hosted non-root controlled SAN HTTPS fixtures, one non-root namespace holder, and a single **one-shot** nft installer in holder's namespace with `CAP_NET_ADMIN`. The nft installer exits after installation. Broker-equivalent verification process runs as non-root with **all capabilities dropped**, read-only filesystem, bounded CPU/RAM/PIDs. The host network namespace, host nft rules, existing Docker networks, actual public routes and other containers are not changed. Temporary containers/network and private ephemeral test SAN certificate/key are cleaned up by a `finally` block. The test does not perform an Internet scan.

## 2. Signed independent broker-side fixture admission

New `broker-scope-ticket.ts`: per-session fresh Ed25519 signing private key in **trusted launcher only**, public key read-only mounted solely into **trusted broker** Docker. Versioned detached signature binds broker executionId, exact plan/job/worker IDs, current claim generation, scope SHA-256, exact controlled HTTPS fixture origin and fixture profile, immutable approved GET paths, max requests, response/total bytes, max runtime, a random nonce and <=9-second expiration. The non-root broker independently verifies signature with the separately mounted trust anchor, all bound identifiers/limits/expiration and signed path equality **before opening its AF_UNIX request socket**. Missing signature, forged values, wrong trusted key, expired grant or wrong execution/generation are rejected. No signing private key or service-role credential is mounted into broker/worker; worker has only compiled bundle and its read-only AF_UNIX broker socket.

An **atomic O_CREAT|O_EXCL nonce-hash marker** in a dedicated host-owned per-job directory (narrow UID-65534 ACL, broker-only mount, **not mounted to worker**) rejects ticket reuse after broker restart on the same trusted host. Actual real Docker opt-in tests exercise successful ticket then replay after container restart, forged signed scope, wrong trust anchor/expiry and refusal of unsigned plan startup. Original HMAC host receipt, database lease generation/hashed-lease fencing, Google-only mandatory TOTP/AAL2, RBAC and live ownership proof checks remain independently enforced by existing code. **Important limit:** The nonce filesystem is host-local, not an atomic multi-host distributed nonce registry. Cross-host worker/controller replay fencing and shared-store cryptographic consumption still need dedicated qualification. The nonce cache also needs production retention/garbage collection.
