Exact HTTPS origin comes from the existing asset registry, never a browser-provided URL. Existing viewer/member roles can inspect records but cannot authorize. Plan record stores consent version, written-reference text, immutable scope SHA-256, proof verification timestamp, exact asset/organization/actor, request idempotency UUID, expiration, revocation actor/time. The separate append-only plan event table and existing audit log retain evidence.

Database RPC `assessment_plan_create`, `assessment_plan_revoke`, `assessment_plan_check` independently call `require_google_aal2` and check active tenant role, matching current verified ownership, proof time identity, exact profile/paths, limits, and immutable idempotency. Plan eligibility is `ELIGIBLE_FOR_FUTURE_REVIEW`, `REVOKED`, `EXPIRED`, or `OWNERSHIP_CHANGED`. All successful responses explicitly contain `executionAllowed:false` and scanningEnabled:false. No execution endpoint is registered, no queue is created and nothing can scan customer networks.

## Independently confined transport architecture

The previously accepted Web passive engine, controlled HTTPS broker, strict worker IPC, DNS/IP public-address checks, real TLS hostname validation, cancel/lease-fencing and saved evidence engines are reused. The new opt-in `pnpm test:confined-broker` starts **TWO separate Docker containers in independent kernel `--network none` namespaces**, one for the broker/controlled temporary SAN HTTPS fixture and one for the credential-free execution worker. Both run non-root UID 65534, read-only root filesystems, `--cap-drop ALL`, no-new-privileges, half CPU, 128 MiB RAM, PID 24, private 16 MiB tmpfs, and one exact mounted compiled bundle. Only a unique **AF_UNIX socket directory** is shared: writable for the broker, read-only for worker; socket `0600`, host directory `0700` plus a narrowly scoped POSIX ACL for container UID 65534, **no world-writable fallback**. Fixture self-signed TLS cert/private key are generated inside broker-only `/tmp`, not shared with worker; only verified response bytes/selected headers enter worker. Worker bundle excludes trusted Supabase/auth/customer controller, synthetic bearer strings and all service credentials. No host firewall, DNS, global Docker policy or unrelated processes modified.

Actual broker namespace inspection verified `NetworkMode=none` and OS denied direct TCP from inside the running broker to public IPv4 `1.1.1.1`, metadata `169.254.169.254`, RFC1918 `10.0.0.1`, public IPv6 `2001:4860:4860::8888`, and private IPv6 `fd00::1`. These are actual socket attempts inside a real container, not synthetic DNS mock. Both secure and intentionally insecure local TLS Web/API comparison fixtures return expected signals. Metadata redirects, oversized bodies, slow responses and cancellation fail closed with no completed assessment evidence. Existing original `--network none` worker and host-side broker regressions remain intact.

**Critical public egress limitation:** the independently confined broker is **deny-all for external IP traffic**, NOT a deployed destination-only/public-IP egress gateway. It retains a controlled localhost fixture and a synthetic resolver override for local test TLS connections. It has not demonstrated OS-enforced public destination-only egress, host DNS A/AAAA answers in a live connected namespace, public TLS CA trust under allowed-only routing or proof that all public routes except authorized IP are blocked. Do not enable customer execution based on these results.

Offline *future* policy `apps/api/src/lib/egress-destination-policy.ts` validates current consent/ownership/proof, exact path/HTTPS method and budgets, every DNS response public, every public IPv4/IPv6 address on an **exact-IP** allowlist, mixed/private/metadata/mapped addresses denied, unexpected still-public rebinding rejected; returns a pinned candidate with **`executionAllowed:false`**. Unit tests cover positive IPv4/IPv6 and negative rebinding, injected private IPs, wrong origin/path, expiry/revocation. **This is a policy contract, not actual public socket routing or an authorization token.** Existing pinned transport performs TLS hostname verification and redirect/response limits; only synthetic loopback TLS executed in this milestone.
