## Implemented customer-facing scope

- `/app/findings` React workspace, organization/asset filters, status/severity sorting, 25-row server-side pages, loading/no-saved-evidence states, selected-finding details, review-only evidence fingerprints, source path/asset/assessment provenance, reviewer rationale and history.
- Owners/admins and analysts import persisted succeeded Web passive or offline API-specification observations into a canonical finding register; no new scans or raw document imports. The original saved observations and assessment jobs stay unchanged. Durable deduplication uses organization, asset, assessment kind, rule identifier and source locator. Repeated import is idempotent.
- Reviewer classification: unreviewed; configuration review; needs evidence; false positive with 12+ character reason; accepted risk with 12+ character reason and owner/admin authority. Accepted-risk decisions cannot be overwritten by analysts. The observed severity estimate remains separate from this human conclusion. Neither source is promoted to a confirmed vulnerability automatically.
- Owner/admin assignment to active permitted organization members; analyst/manager status transitions, append-only comments, same-asset HTTPS evidence URL references (no upload or fetch), reopening and immutable reviewer/event audit history. Viewers may read authorized records only. The database has no direct authenticated writing grants on findings, event, provenance and retest tables.
- `retest_request` saves **awaiting_execution**, checks current verified asset ownership, but **does not initiate a scan**. `retest_compare` accepts only a later succeeded assessment of the same tenant, asset and type, whose completion is strictly after the explicit retest request. Web comparison with unknown/incomplete coverage is inconclusive. API inventory-only comparison is inconclusive. A later observation of the same rule/locator marks `observed_again`; absence under the bounded saved scope is only `not_observed_in_review`, **never** `verified_resolved`.
- Actual `pdf-lib` generated PDF and structured JSON from authenticated tenant-scoped queries. PDF contains organization/asset/scope, timestamps, executive summary, findings ordered by estimated severity, reviewer decisions, remediation, source evidence IDs/fingerprints, review comments/history, retest state, coverage and explicit limitations. Company name LumicSec + scoped organization branding, not fabricated logos/exploits.
- PDF text extracted by the local Poppler `pdftotext` acceptance test confirms actual rule/remediation/reviewer/retest/limitation lines. `pdf-lib` independently parsed the PDF bytes. JSON content tests confirm the same saved provenance and explicit review-only disclaimer.

## Remaining release and product limitations

1. **No live customer Web assessments:** existing `POST /v1/assessments/web` is still HTTP 423. The no-egress container is qualified for synthetic HTTPS only, not hardened destination-limited public networking or hosted orchestration.
2. **No automatic “verified resolved”:** absence in a short passive probe or offline specification is inadequate proof. Requires future dedicated authorized verification engine and independent coverage criteria. A human remediation status is not proof of resolution.
3. **Only saved security observations:** scanner engine still limited to passive Web configuration and offline API specification. No confirmed XSS, SQL injection, CSRF, auth-bypass, business logic or full API runtime exploitation. No fabricated CVEs, CVSS scores, or business impact.
4. **No hosted real-user browser acceptance:** current browser tests use synthetic cookie-backed fixtures, not Supabase SSO/TOTP or a production environment; multi-tenant SQL tested independently under synthetic AAL2 JWT. Full hosted MFA recovery, legitimate customer history and report export remain launch gates.
5. **Reporting limitations:** PDF font used for development renders ASCII-safe text; non-ASCII organization/reviewer text is degraded. No localized/provenance-sealed enterprise design, signing, encryption, evidence screenshots, external file attachments, brand logos or bulk-report job queue. PDF output is unverified for extreme user-generated content beyond current bounded inputs. JSON exports are evidence snapshots, not signed forensic packages.
6. **Security controls pending:** independent pen test, immutable audit offsite retention, report disclosure review, incident controls, strict CSP, security headers and session recovery/revocation. Application authorization must be externally tested before real customers.
7. **Commercial roadmap preserved:** API authenticated runtime+advanced Web assessment engines, risk acceptance policy, safe retest evidence independent review, remediation SLAs/notifications, monitoring, billing and tax/entitlement enforcement, agency tenant management, enterprise SSO/compliance, professional multi-language reporting and production readiness remain future milestones.

The customer UI displays **genuine saved assessments when present**, accurate empty states otherwise. Synthetic observations appear only in explicit test fixtures; no fake production findings are seeded. No paid cloud, production deployment, public customer scans or real customer data changes happened in this qualification.
